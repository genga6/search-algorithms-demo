# アルゴリズム理論ノート ― 計算量・完全性・最適性

各アルゴリズムの「時間計算量・空間計算量・完全性・最適性」が**なぜそう定義できるのか**を、
実装（`src/algorithms/`）と対応させながら書き溜めるノート。実装を追う中で理論が気になったらここへ。

> このノートは実装バッチに合わせて育てる。今は **A. 情報なし探索（BFS / DFS）** まで。

---

## 0. 共通の道具立て

探索を「木」として描くと、4 つの指標はすべて「どう探索するか」から導ける。

記号（roadmap 5 の凡例）:

- **b**（branching factor）… 1 ノードから何手に分岐するか（グリッドの 4 近傍なら最大 4）
- **d** … **解**がある深さ（ゴールまでの最短手数）
- **m** … 探索木全体の**最大**深さ（空間が広いと巨大、循環があると無限にもなりうる）

探索木のイメージ（深さ k の階には約 `b^k` 個のノードがある）:

```
深さ0:            ●               1
深さ1:       ●   ●   ●           b
深さ2:    ●●● ●●● ●●●          b^2
  …                              …
深さd:   .................       b^d   ← ここに解があるとする
```

4 指標の定義:

- **時間計算量** … 生成／展開するノード数のオーダー（≒ 実行時間）
- **空間計算量** … 同時に記憶しておくノード数のオーダー（≒ メモリ）
- **完全性(complete)** … 解が存在するなら必ず見つけられるか
- **最適性(optimal)** … 見つけた解が最良（最小コスト）であることを保証するか

## A. 情報なし探索

### BFS（幅優先）― 浅い層から全部なめる

実装: [`src/algorithms/uninformed/bfs.ts`](../src/algorithms/uninformed/bfs.ts)

| 指標 | 値 | なぜ |
|------|----|------|
| 時間 | O(b^d) | 解に届くには最悪、深さ d の階まで全生成。`1+b+…+b^d ≈ b^d`（最後の階が支配的） |
| 空間 | O(b^d) | フロンティア（`queue`）を丸ごと保持。深さ d の階の約 `b^d` 個が同時にキューに乗る |
| 完全性 | ○ | 階を順になめるので、解が有限深さ d にあれば必ず到達（b が有限なら） |
| 最適性 | ○（単位コスト） | 最初に見つかるのは「一番浅い解」＝最少手数。1 手のコストが一定なら最少手数＝最小コスト |

- **弱点は空間**：`b^d` のフロンティアを全部覚える必要があり、メモリが指数的に膨らむ。
- 最適性は**単位コスト限定**。コストがバラつくと「浅い＝安い」が崩れる → UCS が必要になる伏線。

### DFS（深さ優先）― 一本道を深く潜る

実装: [`src/algorithms/uninformed/dfs.ts`](../src/algorithms/uninformed/dfs.ts)

| 指標 | 値 | なぜ |
|------|----|------|
| 時間 | O(b^m) | 最悪、木全体を深さ m まで調べ尽くす。d より m が大きいと BFS より遥かに悪い |
| 空間 | O(b·m) | 覚えるのは「今の経路（長さ最大 m）＋各段の未展開の兄弟（各段 b 個）」だけ＝線形 |
| 完全性 | △ | 深さ無限や循環があると一本の枝を無限に潜り、他の解に辿り着けない。訪問済み管理＋有限グラフなら○ |
| 最適性 | × | 最初にぶつかった解を返すだけで、浅い／安い保証がない |

- **強みは空間**：`O(b·m)` の線形メモリ（`stack` には一本道分しか積まれない）。BFS の指数と対照的。

### BFS vs DFS ― トレードオフの本質

| | 時間 | 空間 | 完全 | 最適 |
|---|------|------|------|------|
| BFS | O(b^d) | **O(b^d)** 指数 | ○ | ○(単位) |
| DFS | O(b^m) | **O(b·m)** 線形 | △ | × |

**BFS はメモリを犠牲に「最適性・完全性」を買い、DFS は「最適性・完全性」を犠牲にメモリを節約する。**
この対立が、IDDFS（両者のいいとこ取り：BFS 並の最適性を DFS 並の省メモリで）や、
A\*（ヒューリスティックで `b^d` を賢く削る）への布石になる。

## コードとの接続 ― 理論は画面の数字に出る

デモの比較表の列は、この理論の**実測値**そのもの:

- 「展開ノード／生成ノード」列 = 時間計算量の実測（`StatsCounter` の `expanded` / `generated`）
- 「最大フロンティア幅」列 = 空間計算量の実測（`queue` / `stack` が最大何個になったか＝`observeFrontier`）

同じ迷路で BFS と DFS を走らせて「最大フロンティア幅」を比べると、
BFS の方が大きく膨らむ（`b^d`）のが数字で見える。理論の `b^d` vs `b·m` がそのまま現れる。
